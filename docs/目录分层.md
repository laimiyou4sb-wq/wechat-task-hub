# 目录分层契约

> 本文是 `wechat-task-hub/` 的**固定目录分层约定**，为 PyInstaller 打包成 Windows 绿色版 exe 做准备。
> 路径的唯一事实源是 [`app/paths.py`](../app/paths.py)，版本号唯一事实源是 [`app/version.py`](../app/version.py)；
> 本文只描述「什么放在哪一层、谁能写、是否随包」，两者冲突时以代码为准并回来修本文。

## 1. 目标形态

- **一份代码，两种形态**：开发态跑 `python run.py`（项目根即应用根）；打包后跑 `WeChatTaskHub.exe`（exe 所在目录即应用根）。
- 根目录只保留**入口层 + 工程元数据**，其余按职责分层，禁止把运行数据、构建产物、运维脚本堆在根目录。
- `app/` 只放 Python 代码；前端、图标、外部二进制等**资源外置**，便于热更新和减小包体。
- `data/` 是唯一默认可写目录；`output/`、`build/`、`dist/`、`releases/` 是过程/构建产物，不随源码分发。
- **可升级**：升级只替换 `exe + _internal + web + assets + tools`，`data/` 与 `.env` 原地保留。

## 2. 分层总表

| 目录 / 文件 | 层 | 职责 | 可写 | 随 exe / zip |
|---|---|---|---|---|
| `launcher.pyw` | 入口层 | 桌面启动器：拉起服务 + 隧道、健康检查后打开浏览器；同时是 PyInstaller 打包入口 | 否 | 是（编译进 exe） |
| `run.py` | 入口层 | 开发态启动入口（`python run.py [--demo] [--port]`） | 否 | 否（开发用） |
| `app/` | 应用层 | 全部业务代码（FastAPI、SQLite、LLM、推送、同步…），Python 包 | 否 | 是（编译进包） |
| `web/` | 资源层 | 前端静态站点（`index.html`、`settings.html`、`sw.js`…） | 否 | 外置于 exe 同级（包内留一份兜底） |
| `assets/` | 资源层 | 图标等只读资源（`wechat-task.ico`） | 否 | 外置 + 包内兜底 |
| `tools/` | 工具层 | `tunnel.py`、`ui_smoke.py`、`ngrok/ngrok.exe`、`cloudflared.exe` | 否 | 外置于 exe 同级（可独立更新） |
| `scripts/` | 运维层 | 安装 / 启动脚本（`start.bat`、`install_shortcuts.ps1`、`install_task.ps1`、`demo_seed.ps1`） | 否 | **否**（只随源码） |
| `packaging/` | 打包层 | PyInstaller spec、`build.ps1`、版本资源、启动说明 | 否 | 否（构建期使用） |
| `tests/` | 测试层 | pytest（含 `test_layout.py` 契约检查） | 否 | 否 |
| `docs/` | 文档层 | 使用 / 接口 / 分层 / 改造文档与截图 | 否 | 否（README 可随包） |
| `android/` | 客户端层 | 安卓 App 源码与构建产物（独立 Gradle 工程） | 构建时 | 否 |
| `data/` | 运行数据层 | SQLite、日志、pid、`tunnel.json`；**升级保留** | **是** | 否（首启创建） |
| `.env` | 配置层 | 本机配置（token、LLM Key…）；升级保留 | **是** | 否（首启生成） |
| `.env.example` | 配置层 | 配置模板与说明 | 否 | 是（供首启生成 `.env`） |
| `output/` | 过程产物 | 审查截图、日志、迁移/验证证据、历史备份 | 是 | 否 |
| `build/`、`dist/`、`releases/` | 构建产物 | PyInstaller 中间目录 / onedir 产物 / 发布 zip | 构建时 | 否 |
| `requirements.txt`、`requirements-build.txt` | 工程元数据 | 运行依赖 / 构建依赖 | 否 | 否 |
| `README.md`、`.gitignore`、`pytest.ini` | 工程元数据 | 使用说明、忽略规则、测试收集范围 | 否 | README 可随包 |

**命名规则**：根目录只允许出现上表中的入口文件与工程元数据；新增运维脚本放 `scripts/`，构建相关放 `packaging/`，一次性调试证据放 `output/<主题>-<日期>/`。

## 3. 路径契约（唯一事实源 `app/paths.py`）

| 常量 | 开发态 | 冻结态（onedir exe） | 用途 |
|---|---|---|---|
| `FROZEN` | `False` | `True`（`sys.frozen`） | 判断运行形态 |
| `APP_DIR` | 项目根 | `WeChatTaskHub.exe` 所在目录 | 可写安装目录；`.env`/`data`/`web`/`tools` 的锚点 |
| `BUNDLE_DIR` | 项目根 | `sys._MEIPASS`，即 `_internal/`（只读） | 随包只读资源根 |
| `DATA_DIR` | `APP_DIR/data` | `APP_DIR/data` | SQLite、日志、pid、`tunnel.json` |
| `ENV_FILE` | `APP_DIR/.env` | `APP_DIR/.env` | 配置 |
| `WEB_DIR` | `APP_DIR/web`，缺失回落 `BUNDLE_DIR/web` | exe 同级 `web/`，缺失回落包内 | 静态站点 |
| `ASSETS_DIR` | `APP_DIR/assets`，缺失回落 `BUNDLE_DIR/assets` | exe 同级 `assets/`，缺失回落包内 | 图标等只读资源 |
| `TOOLS_DIR` | `APP_DIR/tools` | exe 同级 `tools/` | ngrok/cloudflared 等外置工具 |
| `LOG_DIR` | `DATA_DIR`（日志沿用 `data/*.log` 约定） | 同左 | 日志目录语义别名 |

环境变量覆盖（相对路径一律相对 `APP_DIR` 解析）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `DATA_DIR` | `APP_DIR/data` | 运行数据目录（测试 / 多实例隔离用） |
| `ENV_FILE` | `APP_DIR/.env` | 配置文件 |
| `WEB_DIR` | `APP_DIR/web` | 静态站点目录 |
| `ASSETS_DIR` | `APP_DIR/assets` | 只读资源目录 |
| `TOOLS_DIR` | `APP_DIR/tools` | 工具目录 |
| `DB_PATH` | `DATA_DIR/app.db` | 仅 `config.Settings` 层覆盖 |

### 硬性规则

1. **除 `app/paths.py` 外，`app/` 下任何模块不得再用 `Path(__file__)` 推导目录**；需要路径一律 `from .paths import ...`，新路径先在 `paths.py` 加常量。`tests/test_layout.py` 会做静态检查。
   - 例外：`tools/tunnel.py`、`tools/ui_smoke.py` 允许用 `Path(__file__)` 做**独立运行时的 sys.path 引导**（`python tools\tunnel.py`），但不得用它推导 `data/web/.env` 等运行路径。
2. 运行期要创建目录时调用 `ensure_runtime_dirs()`，不要在业务逻辑里手写 `mkdir`。
3. 运行期只写 `DATA_DIR`（`data/`）与显式指定的 `output/`；`web/`、`assets/` 视为只读资源，热更新时整目录替换。
4. 启动链：`launcher.pyw`（或 `run.py`）→ `app.cli` → `app.main`；打包后服务/隧道子进程用 **exe 自拉起**，不再依赖 `pythonw.exe` 与 `run.py`。
5. 版本号只改 `app/version.py`；运行时 `Settings.version`、FastAPI version、`/api/app/ping`、打包脚本与 Windows 版本资源都从它读取。

## 4. 入口与运维脚本

exe 子命令（`launcher.pyw` 同时是打包入口）：

| 命令 | 行为 |
|---|---|
| `WeChatTaskHub.exe` | 启动器：确保数据源 → 服务 → 隧道 → 打开浏览器 |
| `WeChatTaskHub.exe --serve [--port N] [--demo]` | 前台跑 uvicorn（无窗口子进程，stdout/stderr 落 `data/service.*.log`） |
| `WeChatTaskHub.exe --tunnel [--check/--stop/--once]` | 隧道守护（参数透传 `tools/tunnel.py`） |
| `WeChatTaskHub.exe --stop` | 停隧道 + 停服务 |
| `WeChatTaskHub.exe --version` | 打印版本 |

- **入口①** `launcher.pyw`：用户双击 / 桌面快捷方式 / exe 的入口；打包后由它按 `--serve` / `--tunnel` 自拉起子进程。
- **入口②** `run.py`：开发态入口，内部委托 `app.cli.run_server()`；打包后不随包分发。
- **运维层 `scripts/`**：`start.bat`（开发态命令行启动）、`install_shortcuts.ps1`（桌面/开始菜单快捷方式）、`install_task.ps1`（开机自启 + 防火墙 8765）、`demo_seed.ps1`（演示数据）。
  - 脚本内定位项目根一律用 `$root = Split-Path -Parent $PSScriptRoot`（bat 用 `cd /d "%~dp0.."`），不要写死绝对路径。
  - `scripts/` **不随 exe 分发**；打包后的用户由安装器 / 首启逻辑生成快捷方式与自启。
  - `.bat` 保存为 **ASCII + CRLF、无 BOM**；`.ps1` 保存为 **UTF-8 with BOM**（Windows PowerShell 5.1 才能正确显示中文）。

## 5. 分包边界（哪些进 exe、哪些外置）

- 进包：`app/`、`launcher.pyw`、`web/` 与 `assets/` 的兜底副本、必需 hiddenimports（`openai`、`brotli`、`tzdata`、`uvicorn` 子模块、`tools.tunnel` 等）。
- 外置：`web/`、`assets/`、`tools/`（含 ngrok/cloudflared 约 88 MB）、`.env`、`data/`。
- 不进包：`scripts/`、`packaging/`、`tests/`、`docs/`、`android/`、`output/`、`build/`、`dist/`、`releases/`、`data/`、`.env`。
- 发布 zip 结构见 `packaging/README.md` 与 `packaging/启动说明.txt`。

## 6. 打包后的发行目录（onedir 绿色版）

```
WeChatTaskHub/                  ← 整个目录可整体替换升级
├─ WeChatTaskHub.exe            # 入口（--noconsole）
├─ _internal/                   # Python 运行时 + 依赖（升级时整目录替换）
├─ web/                         # 前端外置（可单独热更新）
├─ assets/                      # 图标等只读资源
├─ tools/                       # ngrok.exe / cloudflared.exe（可选，外置）
├─ data/                        # 首启生成：app.db、日志、pid、tunnel.json
├─ .env                         # 首启生成：APP_TOKEN、PORT、数据源等
├─ .env.example
├─ 启动说明.txt
└─ README.md
```

- 必须 **onedir**：onefile 每次解压临时目录、数据路径不可控、杀软误报高、无法外置 `web/`。
- 升级 = 替换 `WeChatTaskHub.exe` + `_internal/` + `web/` + `assets/` + `tools/`，**不动 `data/` 与 `.env`**。
- 开发态与冻结态目录一一对应：`APP_DIR` 两侧都是「exe/项目根」，所以代码不需要区分两套相对路径。

## 7. 新增文件放哪里（决策树）

1. 是 Python 业务代码？→ `app/`（路径用 `app.paths`）。
2. 是前端 / 图标等只读资源？→ `web/` / `assets/`。
3. 是第三方可执行文件或开发辅助脚本（隧道、冒烟）？→ `tools/`。
4. 是安装、快捷方式、启动批处理？→ `scripts/`。
5. 是 PyInstaller spec、构建脚本、版本资源？→ `packaging/`。
6. 是测试？→ `tests/`；是文档？→ `docs/`。
7. 是运行期产生的数据 / 日志 / 状态？→ `data/`（代码里用 `DATA_DIR`）。
8. 是调试截图、验收报告、一次性脚本输出？→ `output/<主题>-<日期>/`。
9. 是构建产物？→ `build/`、`dist/`、`releases/`（全部 gitignore）。

## 8. 相对旧结构的变更

| 旧位置 | 新位置 | 说明 |
|---|---|---|
| 根目录 `start.bat` / `install_shortcuts.ps1` / `install_task.ps1` / `demo_seed.ps1` | `scripts/` 下同名文件 | 脚本内部用 `$PSScriptRoot` 反推项目根 |
| 根目录 `output_server.log` / `output_server.err.log` | `output/` | 纯过程日志 |
| 新增 | `app/paths.py`、`app/version.py`、`app/cli.py` | 路径 / 版本 / 命令行唯一入口 |
| 新增 | `packaging/`、`requirements-build.txt` | 打包层 |
| `launcher.pyw` / `run.py` | 仍在根目录 | 入口层，PyInstaller 入口是 `launcher.pyw` |

已安装的桌面快捷方式仍指向根目录 `launcher.pyw`，不受本次调整影响；若快捷方式丢失，运行 `scripts\install_shortcuts.ps1` 重新生成。

## 9. 校验清单（改目录/加文件后自查）

```powershell
# 1) 路径契约单测（含冻结态模拟、禁止 Path(__file__) 静态检查）
python -m pytest tests/test_layout.py -q

# 2) 当前进程解析出的路径
python -c "from app.paths import describe; import json; print(json.dumps(describe(), ensure_ascii=False, indent=2))"

# 3) 全量测试
python -m pytest tests -q

# 4) 用临时数据目录起服务，确认静态站点/健康检查正常
$env:DATA_DIR = Join-Path $env:TEMP "wxtask-check"
python run.py --demo --port 8799
# 另开终端：curl http://127.0.0.1:8799/api/health
```

人工检查：

1. 根目录只剩入口层 + 工程元数据（`launcher.pyw`、`run.py`、`README.md`、`requirements*.txt`、`.env*`、`.gitignore`、`pytest.ini` 等），没有散落的 `.bat` / `.ps1` / 日志。
2. `grep -rn "Path(__file__)" app/`：只应命中 `app/paths.py`。
3. 文档中涉及脚本的命令一律写 `.\scripts\xxx`；涉及运行数据的写 `data\`；涉及构建产物的写 `dist\` / `releases\`。
4. 分层变更同步更新本文与 [README.md](../README.md) 的「目录结构」一节。

## 10. 已知注意事项

1. `data/` 不要放 OneDrive / 网络盘：SQLite WAL 在同步盘上易损坏。
2. `.env` 与 `data/` 必须在 `APP_DIR`，不要放进 `_internal/`（升级会整目录替换、`_MEIPASS` 只读）。
3. `web/` 外置是有意为之：前端改版只需替换 `web/`，无需重装 exe；缺失时才回落包内兜底。
4. `tools/` 的二进制外置：避免 exe 体积膨胀、杀软误报和更新困难；冻结态隧道逻辑用 `--tunnel` 自拉起，不再依赖外置 `tunnel.py`。
5. 无控制台 exe 的 `stdout/stderr` 由 `app.cli._ensure_stdio()` 落到 `data/service.out.log` / `service.err.log`；排查启动问题先看这两个文件与 `data/launcher.log`。
6. 只支持 onedir；不要用 onefile（见第 6 节）。
7. 首次双击 exe（无参启动器）时，`app/config.ensure_env_file()` 会在 `APP_DIR` 生成 `.env`：复制 `.env.example` 并把 `APP_TOKEN` 换成随机串（已有 `.env` 不覆盖）。`--serve` / `--tunnel` / `--stop` / `--version` 等管理/子进程命令不生成配置文件，避免副作用。
