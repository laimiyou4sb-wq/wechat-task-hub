## 1. 交付内容

### 1.1 设置页「05 运行状态」卡（A）
- 左导航与卡片顺序变为 **01 大模型 / 02 手机推送 / 03 消息范围与白名单 / 04 身份与判定 / 05 运行状态 / 06 手机 App / 07 其余配置**。
- 数据全部来自 `GET /api/health`，五组快照：
  - 数据源：类型、连接状态、实时流数、最近消息时间、最近错误（仅非空显示）；
  - 补采：启用/关闭、间隔、默认回看、上次补采结果（分钟/会话/新增消息/新建/更新待办/时间），失败显示原因；
  - 置顶：模式中文映射、置顶数、是否就绪、自定义数；
  - 事项账本：开放事项、缓冲会话、缓冲消息；
  - 概况：LLM、推送通道、待办数、仅新消息、版本。
- 三个操作：「立即补采」（可选回看 30 分钟 / 120 分钟 / 6 小时 / 24 小时，`POST /api/catchup`）、「同步置顶」（`POST /api/pinned/refresh`）、「刷新状态」；按钮 loading/禁用、结果行、toast、`ok=false` 降级提示、health 读取失败可重试。

### 1.2 任务详情「所属事项」+ 来源条数（B）
- 桌面右栏与手机抽屉在「备注」之后、「来源原文」之前新增「所属事项」：事项标题、摘要（与标题重复时省略）、群名、状态标签（归纳中 / 已关闭）。
- `GET /api/tasks/{id}` 返回的 `event` 段此前被前端丢弃，现已消费；手动添加任务（无 event）不显示该区块。
- 来源原文标题补「来源原文 · N 条」；列表卡片在 `source_count > 1` 时显示「来源 N 条」小标签（title 提示「由 N 条消息归纳」）。

### 1.3 数据源断开横幅（C）
- `health.data_source !== 'demo'` 且 `source.configured=false` 或 `source.connected=false` 时，主页面顶部显示 warn 横幅：
  - 未配置：「未配置数据源：暂时不会自动生成待办，请检查设置」；
  - 未连接：「数据源未连接：暂时不会自动生成待办，请确认微信/数据源已启动」+ `source.last_error`（截断 80 字）。
- 横幅带「重试」与「去设置」（带当前 token）；错误横幅优先、恢复后自动消失、demo 实例不显示。

### 1.4 手机端归档入口（D）
- 手机端仍保持 4 个 tab（今天 / 本周 / 以后 / 已完成），不新增第 5 个。
- 进入「已完成」后出现分段：`已完成 N` / `已忽略 N` / `稍后 N`（仅 <1024px 且处于归档视图时显示）；切到已忽略/稍后时底部「已完成」tab 仍保持选中。
- 手机抽屉对已完成/已忽略/稍后任务：主操作「恢复为待办」+「删除」（二次确认）；删除后关闭抽屉并刷新列表/计数。
- 列表卡片「恢复」按钮沿用既有逻辑；320px 宽度下三个分段不挤压。

### 1.5 删除 CalDAV 弃用卡 + 清理废弃方案代码（E）
- 设置页整块删除「手机同步（CalDAV · 已弃用）」卡片、左导航项与所有 CalDAV 前端代码；「其余配置」08→07；App 卡文案去掉 Tasks.org/Tailscale 旧引用。页面不再请求 `/api/caldav/*`。
- 后端彻底删除旧方案：
  - 删除 `app/caldav.py`（内嵌 Radicale + VTODO 双向同步）与 `tests/test_caldav.py`（18 例）；
  - 删除 `GET /api/caldav/info`、`POST /api/caldav/sync`；`health()` 移除 `caldav` 字段；
  - 删除 `config.py` 的 5 个 `caldav_*` 字段与 `caldav_auth`；`main.py` 不再挂载 `/dav`；
  - `requirements.txt` 删除 `radicale` / `a2wsgi` / `icalendar` / `caldav` / `requests`（均已确认仅旧 CalDAV 使用）；
  - `.env.example` 删除 CalDAV 段；用户 `.env` 中的 CalDAV 段也已在本次清理中删除（旧配置若残留会被忽略）。
- 新增回归：`/api/caldav/info` 404、`/api/caldav/sync` 404/405（静态兜底）、health 不含 caldav。

### 1.6 资源与缓存
