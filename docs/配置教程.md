# 配置教程（从零到手机收到待办）

> 目标：电脑版微信收到消息 → 自动归纳成待办 → 推到手机 → 手机浏览器里勾选完成。
> 默认数据源：**WeChatDataAnalysis**（桌面端本地只读 API；本项目每 120 秒按每会话 localId 游标采集一轮，并周期性深扫晚到消息）。
> 全部配置都在 `D:\微信通知总结\wechat-task-hub\.env` 里，改完重启服务生效。

---

## 0. 先改访问令牌

打开 `.env`，把 `APP_TOKEN` 改成随机串（手机访问靠它，不要用默认值）：

```ini
APP_TOKEN=wt-换成你自己的随机串
```

生成一个：

```powershell
python -c "import secrets; print('wt-' + secrets.token_hex(8))"
```

## 1. 安装并启动 WeChatDataAnalysis（负责提供微信消息）

1. 下载安装：<https://github.com/LifeArchiveProject/WeChatDataAnalysis/releases/latest>
   （Windows 选 `Setup.exe`；你机器上已装在 `%LOCALAPPDATA%\Programs\WeChatDataAnalysis`）
2. 启动 `WeChatDataAnalysis`，按界面引导登录**电脑版微信 4.x**，完成账号选择与数据库解密；
3. 保持 WeChatDataAnalysis 在运行（托盘/后台即可），它会提供本地 API：
   - 健康检查：<http://127.0.0.1:10392/api/health>
   - 接口文档：<http://127.0.0.1:10392/docs>
   - 本项目通过它的本地只读接口按每会话 localId 游标采集消息（启动 8 秒后先采一次，之后每 120 秒一轮；另有晚到消息深扫兜底）
4. 确认 `.env`：

```ini
DATA_SOURCE=wcda
WCDA_BASE=http://127.0.0.1:10392
WCDA_CATCHUP_SECONDS=120        # 采集轮间隔；启动 8 秒先按 localId 游标采一次，之后每轮续采
WCDA_DEEP_SCAN_MINUTES=60       # 晚到消息深扫间隔（分钟；0=关闭），按时间窗重扫、不推进游标
WCDA_DEEP_SCAN_LOOKBACK_MINUTES=1440  # 深扫回看窗口 = 晚到消息兜底上限（默认 24 小时，不是 WCDA_CATCHUP_MAX_HOURS）
MESSAGE_MAX_ATTEMPTS=3          # 单条消息处理失败最大重试次数；超限进失败队列并告警，整体性故障不计次数
```

> 如果它在设置里改过端口，把 `WCDA_BASE` 改成对应端口。
> 本项目不直接解密微信数据库，只消费 WeChatDataAnalysis 的本地只读接口。

## 2. 配置大模型（负责“归纳总结”）

推荐 DeepSeek（便宜、中文好）：<https://platform.deepseek.com> → 注册/登录 → **API keys** → 创建 Key。

### 方式 A：网页里填（推荐，保存即生效，不用重启）

1. 打开任务表（启动时打印的地址，如 `http://127.0.0.1:8765/?token=...`）；
2. 点右上角 **⚙**，进入设置页；
3. 填 **API Key**（`sk-...`）、确认 Base URL、模型名；
4. 点「保存」——立即生效；点「测试连接」可以验证 Key 是否可用；
5. 想换回规则模式：点「清除 Key」。

> Key 会写回项目根目录 `.env`，下次启动继续有效；页面只显示掩码（如 `sk-…abcd`）。

### 方式 B：直接改 `.env`（改完重启）

```ini
LLM_ENABLED=1
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-你的key
LLM_MODEL=deepseek-chat
# 同一轮内按该条数分片多次归并（默认 40 条/批；0=不分批）。
# 分片避免单次 prompt 过大，以及「最多 8 个事项 / 12 个任务」上限在洪峰下静默饱和，
# 命中上限会计入 /api/health 的 extraction_cap_hits，设置页「运行状态 → 采集」可见。
LLM_BATCH_MESSAGES=40
```

> 不填 Key 也能用：会退化为本地规则提取（只识别含“记得/截止/报名/明天/几点”等行动词的消息），准确率低一些。
> 想用本地模型（Ollama）：`LLM_BASE_URL=http://127.0.0.1:11434/v1`，`LLM_API_KEY=ollama`，`LLM_MODEL=qwen2.5:7b`。
> LLM 调用失败会自动回退规则模式：此时采集仍正常跑（`ok=true`），但 `degraded=true`、`last_llm_error` 非空，主页会显示降级横幅。

## 3. 配置手机推送（Bark 或 ntfy，二选一）

> **推荐方式**：打开任务表 → 右上角 **⚙** → 「手机推送」卡片，直接填 Bark / ntfy 并点「发送测试推送」。保存后立即生效，无需重启。
> 下面是直接改 `.env` 的等价方式（改完需重启）。

### iPhone：Bark

1. App Store 搜 **Bark** 安装；
2. 打开 App，首页会显示一条你自己的推送地址，形如
   `https://api.day.app/AbCdEf123456`；
3. 填入 `.env`：

```ini
PUSH_BARK_URL=https://api.day.app/你的key
```

### Android（或想跨平台）：ntfy

1. 应用商店安装 **ntfy**（或浏览器打开 <https://ntfy.sh>）；
2. 订阅一个**足够随机**的主题，例如 `wx-tasks-7f3k9m2xq8`；
3. 填入 `.env`（主题两边必须完全一致）：

```ini
NTFY_SERVER=https://ntfy.sh
NTFY_TOPIC=wx-tasks-7f3k9m2xq8
```

> 公共 ntfy.sh 上知道主题名的人就能看到消息，所以主题要随机；在意隐私可自建 ntfy 服务器并填 `NTFY_SERVER` + `NTFY_TOKEN`。

## 4. 选择监控范围（置顶 / 自定义 / 全部）

推荐在 **⚙ → 消息范围与白名单** 里选，保存即生效：

| 模式 | 含义 |
|---|---|
| `pinned` **仅置顶聊天**（推荐） | 自动同步微信里置顶的群聊和私聊，每 1 分钟刷新 |
| `pinned_custom` 置顶 + 自定义 | 置顶聊天 + 手动名单 |
| `custom` 仅自定义名单 | 只处理手填的群名 / 联系人备注 / wxid |
| `all` 全部 | 不过滤，消息量大、噪音多 |

对应 `.env`：

```ini
WHITELIST_MODE=pinned
PINNED_REFRESH_SECONDS=60
GROUP_WHITELIST=                # 自定义名单；pinned 模式下可留空
INCLUDE_PRIVATE=1               # 是否包含私聊
# 采集会自动补齐停机 / 断网期间漏掉的消息；已处理过的不会重复归纳
ME_NAMES=你的外号               # 手动补充别名（群昵称会自动从微信同步，一般不用填）
IDENTITY_FILTER=1               # 丢弃「明确 @ 别人 / 点名别人」的消息
IDENTITY_FUZZY=1                # 开启错别字 / 同音模糊匹配
```

> 自定义名单支持逗号或换行分隔，例如 `项目群,课程群,张三,wxid_xxxx`。
> `pinned` 模式只处理置顶会话；如果发现某些聊天没进来，把它在微信里置顶，或改用 `pinned_custom` 加名单。

## 4.1 身份判定：@ 我 / 点名我才生成待办

设置页 **⚙ → 身份与判定** 可以直接看到并修改：

- **自动识别**：我的 wxid（WeChatDataAnalysis `/api/current-account`）、当前群昵称（`/api/chat/contacts/group_members`）、通讯录昵称/微信号；
- **手动别名**：外号、同音字、错别字写法都可以填，每行一个；
- **判定测试**：粘贴一句话 + 选群，立即看到判定（需要我参与 / @所有人 / 指向他人·丢弃 / 未指定）；
- **最近过滤**：列出被丢弃的消息（时间、群、发送者、命中对象、原文），方便复盘误判。

规则：微信原生 @ 名单（wxid）最可靠；正文 `@昵称`、开头直呼、`让/请/叫…某人` 指派句式、回复我，
按「明确指向谁」判断。**没有明确指向某个人的群公告不会被过滤**，仍按原来的 LLM 逻辑生成待办。
关闭 `IDENTITY_FILTER` 即可完全回到旧行为。

## 5. 调试期建议调整参数

首次联调时把「采集轮间隔」调短（消息更快进待办；想更快兜住晚到消息也可把深扫间隔调小），并暂时关掉免打扰（否则 23:00–07:30 不推送）：

```ini
WCDA_CATCHUP_SECONDS=30
WCDA_DEEP_SCAN_MINUTES=10
PUSH_QUIET_START=00:00
PUSH_QUIET_END=00:00
```

正常使用再改回：

```ini
WCDA_CATCHUP_SECONDS=120
WCDA_DEEP_SCAN_MINUTES=60
PUSH_QUIET_START=23:00
PUSH_QUIET_END=07:30
```

## 7. 逐项自检

### 7.1 服务与数据源

```powershell
Invoke-RestMethod "http://127.0.0.1:8765/api/health" | ConvertTo-Json -Depth 5
```

期望：

```json
"data_source": "wcda",
"source": { "type": "wcda", "configured": true, "connected": true, "last_collect_at": "..." },
"wcda":   { "configured": true, "connected": true },
"llm":    { "configured": true },
"push":   { "bark": true },          // 或 "ntfy": true
"collection": { "enabled": true, "mode": "watermark", "cursor_sessions": 13,
                "deep_scan_minutes": 60, "failed_messages": 0, "failed_sessions": 0,
                "degraded": false, "degraded_reasons": [], "partial": false,
                "llm_batches": 3, "llm_fallbacks": 0, "llm_fallback_total": 0,
                "last_llm_error": null, "llm_fallback_streak": 0,
                "extraction_cap_hits": 0, "messages_without_task": 2,
                "read_rows": 120, "duplicate_rows": 0, "read_ratio": 1.0,
                "llm_batch_messages": 40 },
"version": "0.3.0"
```

- `source.connected=false`：采集轮失败 / WeChatDataAnalysis 没启动、API 端口不对、微信没登录或没完成解密，或 sessions（会话列表）接口失败；
- `source.connected=null`：首轮采集尚未完成（等待中），启动 8 秒后的首轮采集完成后会自动变为 `true`；
- 采集状态可在设置页「运行状态 → 采集」查看：上次采集时间、每轮结果、会话水位 / localId 游标数、待处理与失败队列消息/会话数，以及采集降级 / LLM 分片与回退 / 抽取上限 / 未生成待办 / 上次深扫 / 分页读取放大；
- `collection.failed_messages > 0`：有消息重试超限进入失败队列，设置页点「重试失败队列」或调 `POST /api/collect/failed/retry` 放回待处理；失败不影响同会话后续消息；短时 LLM / 网络等整体性故障（大积压前 30 条隔离探测样本全失败）不计重试次数、下一轮自动重试，不会灌进失败队列；
- `collection.degraded=true`：本轮采集降级，`degraded_reasons` 给出原因码——`llm_fallback`（LLM 回退规则模式）、`extraction_cap`（抽取命中 8 事项 / 12 任务上限，可能漏建）、`partial_failure`（部分会话失败）、`sustained_failure`（连续多轮整体性失败）、`sessions_unavailable`（会话列表接口失败）、`collect_error`（采集轮未捕获异常）；其中**仅 LLM 回退时 `last.ok` 仍为 `true`**（UI 显示“降级”而非“失败”），`last_llm_error` 记录最近一次 LLM 错误；
- `collection.partial=true` / `last.ok=false`：本轮有会话读取/处理失败（含部分失败、整体性失败、sessions 接口失败）；`partial=true` 表示本轮仍有消息被处理（部分成功），`sessions_failed` 是失败会话 id 列表、`sessions_failed_count` 是失败会话数；主页顶部会出现「采集降级」warn 横幅，若 `source.connected` 仍为 `true` 但 `source.last_error` 非空，则显示「采集不完整」横幅；
- `collection.read_rows` / `duplicate_rows` / `read_ratio`：分页读取行数 / 重复行数 / 读取放大倍数，只是观测值（按 createTime 翻页导致读取放大），不是数据错误；
- `llm.configured=false`：没填 `LLM_API_KEY`（仍可用规则模式）。

让朋友（或你自己另一个号）在监控的群里发一条：

## 8. 手机访问

1. **同一 Wi-Fi（日常推荐）**：手机浏览器打开启动时打印的「手机访问」地址（带 `?token=`）；
2. **外网 / 校园网隔离**：用 **ngrok 免费固定域名**（HTTPS，跨网络也能用）：
   - 一次性配置：在项目目录运行 `powershell -ExecutionPolicy Bypass -File .\tools\ngrok_setup.ps1`，
     按提示注册 ngrok（免费）并粘贴 authtoken，见 [手机同步.md](手机同步.md) 第 4 节；
   - 之后双击桌面「微信待办」会自动把隧道一起拉起来；`python tools\tunnel.py --check` 查看公网地址和链路状态，
     公网地址也写在 `data/tunnel.json` 里；
   - `.env` 的 `APP_BASE_URL` **留空即可**：远程地址由隧道自动提供，不需要手填；
3. **手机 App（推荐）**：装自研「微信待办」安卓 App → 电脑网页右上角 **⚙ →「手机 App」→ 复制配对码** →
   App「设置 → 配对 → 粘贴配对码」→ 测试连接。在家自动走局域网、出门自动走 ngrok；
4. Safari/Chrome 菜单 → **添加到主屏幕**，之后像 App 一样用；
5. 手机打不开：
   - 同一 Wi-Fi：管理员运行 `.\scripts\install_task.ps1`（放行防火墙 8765）；公司/学校网络可能禁止设备互访 → 用 ngrok；
   - 外网：电脑是否开机联网、`python tools\tunnel.py --check` 是否显示「结论：健康」、`data\tunnel.log` 有没有报错。

### 8.1 把待办同步到安卓手机（自研 App + 配对码）

> 完整步骤、ngrok 注册、免费额度、常见问题见 **[docs/手机同步.md](手机同步.md)**；这里只列最短路径。

1. 电脑端服务已在运行（双击桌面「微信待办」），手机安装自研 App（`android/dist/app-debug.apk`，或用 `adb install`）；
2. 电脑网页右上角 **⚙** →「**手机 App（直连同步）**」卡片 → 点「复制配对码」
   （配对码里已含 token + 局域网地址，配好 ngrok 后还会含 `https://xxx.ngrok-free.dev`（或 `.app`）远程地址）；
3. 手机 App：**设置 → 配对 → 粘贴配对码 → 保存 → 测试连接**；
4. 在 App 里「立即同步」验证：电脑网页新建一条任务，App 下拉刷新能看到；手机勾选完成，电脑端会同步为「已完成」；
5. 出门在外想用：按 [手机同步.md](手机同步.md) 第 4 节配好 ngrok，**重新复制一次配对码**在 App 里重新配对即可；
6. 旧方案（Tasks.org / DAVx5 / CalDAV / Tailscale）**已从代码中移除**，不需要任何配置；旧 `.env` 里残留的 `CALDAV_*` 行会被忽略，可手动删除。

## 9. 常见问题

| 现象 | 排查 |
|---|---|
| `source.connected=false` | WeChatDataAnalysis 是否运行、`http://127.0.0.1:10392/docs` 是否可打开、微信是否登录/解密完成 |
| `last_error` 含 `No chat accounts found` | WeChatDataAnalysis 还没完成账号配置：打开它的界面，选择账号并按引导解密一次（或填 db key/db_storage 路径） |
| 收不到消息 | `GROUP_WHITELIST` 是否把群过滤掉了（先留空）；WeChatDataAnalysis 是否在运行、账号已选择并完成解密 |
| 晚到消息没采到 | 确认 `WCDA_DEEP_SCAN_MINUTES` 未设为 `0`（默认每 60 分钟深扫一次、回看 24 小时）；晚到消息兜底上限就是这个回看窗口 `WCDA_DEEP_SCAN_LOOKBACK_MINUTES`（默认 24 小时，不是 `WCDA_CATCHUP_MAX_HOURS`），断网更久需调大（代价：每次深扫多翻页）；停机较久会按 localId 游标分页补齐 |
| 消息进了失败队列 | 设置页「运行状态 → 采集」看失败队列与 `last_error`，点「重试失败队列」或调 `POST /api/collect/failed/retry` 放回待处理（`MESSAGE_MAX_ATTEMPTS` 默认 3）；大积压遇到整体性故障（LLM/网络中断）不计次数、下轮重试，不会进失败队列；连续 3 轮仍整体性失败会推送「采集持续失败」告警，并把 `last.ok` 标为 `false`、`degraded=true`（`degraded_reasons` 含 `sustained_failure`），设置页与主页横幅同步可见 |
| 主页出现「采集降级」/「采集不完整」 | 「采集不完整」= `source.connected` 仍为 true 但 `source.last_error` 非空（部分会话读取/处理失败），下轮自动重试；「采集降级」看设置页「运行状态 → 采集」：`llm_fallback` = LLM 调用失败回退规则模式（`last_llm_error` 有原因）；`extraction_cap` = 本轮命中 8 事项 / 12 任务上限，可调小 `LLM_BATCH_MESSAGES`（默认 40 条/批）让每批更小；`partial_failure` / `sessions_unavailable` = 部分会话读取失败，下轮自动重试；`collect_error` = 采集轮未捕获异常（看 `reason` / 日志） |
| 有消息但没待办 | 消息被当成闲聊过滤了；或没配 LLM Key 且不含行动词 |
| 有任务但没推送 | 是否在免打扰时段；`PUSH_*` 是否配置；先跑 `/api/push/test` |
| 手机打不开 | 同一 Wi-Fi：防火墙/同一网段（`.\scripts\install_task.ps1` 放行 8765）；外网：电脑是否在线、`python tools\tunnel.py --check` 是否「结论：健康」、看 `data\tunnel.log` |
| App 连不上 / 提示 401 | 回电脑网页 ⚙「手机 App」重新复制**配对码**粘到 App（含地址 + token）；`.env` 的 `APP_TOKEN` 改过必须重新配对；详见 [手机同步.md](手机同步.md) |
| ngrok 隧道起不来 / `ERR_NGROK_105` | authtoken 无效或没配：重新运行 `tools\ngrok_setup.ps1`；详细错误看 `data\tunnel.log` |
| 外网突然不通 | 免费额度 1GB/月、20000 请求/月（<https://dashboard.ngrok.com/usage>）；电脑休眠/断网恢复后 `tools\tunnel.py` 会自动重连 |
| 端口被占用 | 改 `.env` 的 `PORT`，或关掉旧的 `python.exe` |

> 晚到消息（写入晚、业务时间旧）由 `WCDA_DEEP_SCAN_MINUTES`（默认 60 分钟）周期性深扫兜底，兜底上限是 `WCDA_DEEP_SCAN_LOOKBACK_MINUTES`（默认 24 小时，不是 `WCDA_CATCHUP_MAX_HOURS`），断网/休眠更久需调大该值；`WCDA_DEEP_SCAN_MINUTES` 设为 `0` 表示关闭深扫。

## 10. 安全提醒

- `.env` 含模型 Key、推送 Key、ngrok authtoken（在 `%LOCALAPPDATA%\ngrok\ngrok.yml`），**不要**提交到 Git 或发群里；
- 手机访问令牌就是密码，泄露后别人能看/改你的待办；泄露后改 `.env` 的 `APP_TOKEN` 并重启，旧配对码立即失效；
- ngrok 域名公网可访问：拿到域名只能打开网页外壳，**任务数据接口都要 `X-Auth-Token`**；但域名 + 配对码一起泄露就危险，配对码不要外传；
- 手机 App 支持「换 token 后重新配对」；电脑休眠/断网时手机显示离线，恢复后自动补同步；
- 不要让 ngrok 隧道指向除 8765 以外的服务，也不要把 8765 端口直接暴露到公网（不要做路由器端口映射）；
- 旧 CalDAV 方案（Tasks.org/DAVx5）已从代码中移除；
- 只处理本人账号、本人设备的数据，遵守微信条款与当地法律。
