# 开源发布与自动更新方案（GitHub Releases 驱动）

> 目标：开源后，开发者打 tag 发版 → 已安装的 App 及时感知 → 设置页/首页提示 → 点击「更新」自动下载、校验、重启安装。
>
> 前提：先完成 [封装成应用-改造清单](封装成应用-改造清单.md) 的 P0（路径、入口、PID、版本）。特别是 `--stop` 必须能干净停进程，否则更新替换文件会失败。

---

## 一、总体架构

```
开发者                           GitHub                         用户机器
──────                           ──────                         ─────────
git tag v0.3.0 ──push──▶ Actions: build & test
                              │
                              ├─ WeChatTaskHub-Setup.exe
                              ├─ WeChatTaskHub-portable.zip
                              ├─ sha256sums.txt
                              └─ latest.json      ──▶ GitHub Release（latest 稳定 URL）
                                                              │
                                                              ▼
                                                   App 后台每 6h / 启动时 / 手动
                                                   GET .../releases/latest/download/latest.json
                                                              │
                                            版本更高 → 设置页卡片 + 首页 banner
                                                              │  （可选 Bark / ntfy 推手机）
                                                              ▼
                                                   点击「更新」→ 服务端下载安装包
                                                   → 校验 sha256 → 静默运行安装器
                                                   → 旧进程退出 → 覆盖安装 → 自动重开
```

**为什么用安装器（Inno Setup）而不是自己替换 exe**：运行中的 exe 无法覆盖，自己要写等待退出、robocopy、回滚、隐藏窗口；Inno 自带 `CloseApplications / RestartApplications`、安装日志、卸载与版本资源，可靠得多。绿色版 zip 再补一个 `updater.bat` 作为兜底。

## 二、发布侧（GitHub Actions）

### 1. 版本号单一来源

新增 `app/version.py`：

```python
VERSION = "0.3.0"
```

`Settings.version`（[config.py:156](../app/config.py#L156)）、FastAPI `version`（[main.py:259](../app/main.py#L259)）、`/api/health` 返回的 `version`（[service.py:1145](../app/service.py#L1145)）全部引用它。发版时先改这里，tag 必须等于 `v{VERSION}`，CI 里校验。

### 2. Release 资产（文件名固定，URL 才稳定）

| 资产 | 说明 |
|------|------|
| `WeChatTaskHub-Setup.exe` | 安装版，一键更新的主通道 |
| `WeChatTaskHub-portable.zip` | 绿色版，解压即用 |
| `latest.json` | 更新清单（App 只读这个） |
| `sha256sums.txt` | 全部资产的哈希 |
| `latest.json.minisig` | 可选：签名（走镜像时防篡改） |

固定文件名让这两个 URL 永远有效：

```
清单：https://github.com/<owner>/<repo>/releases/latest/download/latest.json
安装：https://github.com/<owner>/<repo>/releases/latest/download/WeChatTaskHub-Setup.exe
```

### 3. `latest.json` 结构

```json
{
  "version": "0.3.0",
  "tag": "v0.3.0",
  "channel": "stable",
  "published_at": "2026-11-02T10:00:00Z",
  "notes": "修复……；新增……",
  "min_app_version": "0.2.0",
  "assets": {
    "installer": {
      "url": "https://github.com/<owner>/<repo>/releases/download/v0.3.0/WeChatTaskHub-Setup.exe",
      "size": 41234567,
      "sha256": "…"
    },
    "portable": {
      "url": "https://github.com/<owner>/<repo>/releases/download/v0.3.0/WeChatTaskHub-portable.zip",
      "size": 52345678,
      "sha256": "…"
    }
  }
}
```

- `min_app_version`：手机 App 依赖的接口大改时填，旧版提示「请先升级手机 App」或禁止更新。
- 预发布通道：tag `v0.3.0-beta.1` → `channel: beta`，只有 `UPDATE_CHANNEL=beta` 的用户能看到。

### 4. `.github/workflows/release.yml`（可直接套用）

```yaml
name: release
on:
  push:
    tags: ["v*"]

permissions:
  contents: write

jobs:
  build:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.13"
      - name: Install deps
        run: |
          pip install -r requirements.txt -r requirements-build.txt
      - name: Test
        run: pytest -q
      - name: Check tag == app/version.py
        shell: pwsh
        run: |
          $v = (Select-String -Path app/version.py -Pattern 'VERSION = "(.+)"').Matches.Groups[1].Value
          if ("v$v" -ne "${{ github.ref_name }}") { throw "tag 与 app/version.py 不一致" }
      - name: Build portable (PyInstaller onedir)
        run: pyinstaller --noconfirm --clean build/wechattaskhub.spec
      - name: Build installer (Inno Setup)
        run: |
          choco install innosetup -y --no-progress
          & "${env:ProgramFiles(x86)}\Inno Setup 6\ISCC.exe" build/installer.iss
      - name: Build manifest
        shell: pwsh
        run: python build/make_latest.py --tag "${{ github.ref_name }}"
      - name: Publish release
        uses: softprops/action-gh-release@v2
        with:
          files: |
            dist/WeChatTaskHub-Setup.exe
            dist/WeChatTaskHub-portable.zip
            dist/latest.json
            dist/sha256sums.txt
          generate_release_notes: true
          prerelease: ${{ contains(github.ref_name, '-') }}
```

`build/make_latest.py` 读取 `app/version.py`，对两个资产做 `sha256`，写成上面的 `latest.json`。

### 5. 安装器关键配置（`build/installer.iss`）

```
AppId={{8F1D...-稳定 GUID}}
AppName=微信待办
AppVersion={#MyAppVersion}
DefaultDirName={localappdata}\Programs\微信待办
PrivilegesRequired=lowest
CloseApplications=yes
RestartApplications=yes
AppMutex=WeChatTaskHubSingleInstance

[Files]
Source: "dist\WeChatTaskHub\*"; DestDir: "{app}"; Flags: recursesubdirs ignoreversion
Source: "web\*"; DestDir: "{app}\web"; Flags: recursesubdirs ignoreversion

[Icons]
Name: "{autodesktop}\微信待办"; Filename: "{app}\WeChatTaskHub.exe"
Name: "{autoprograms}\微信待办"; Filename: "{app}\WeChatTaskHub.exe"

[Run]
Filename: "{app}\WeChatTaskHub.exe"; Flags: nowait postinstall skipifsilent

[UninstallDelete]
; 不写 data / .env → 卸载后用户数据保留
```

App 启动时创建同名命名互斥量（`CreateMutexW`），安装器才能识别并关闭旧进程。

## 三、客户端：检查、通知、更新

### 1. 新增 `app/update.py`

```python
class UpdateManager:
    def __init__(self, settings, pusher): ...
    async def start(self):            # service.start() 里加入后台任务
        self._task = asyncio.create_task(self._loop())
    async def check(self, force=False) -> dict: ...
    async def download(self) -> dict: ...
    async def apply(self) -> dict: ...
```

- **检查**：`htpx` GET `latest.json`（默认 GitHub latest URL，可被 `UPDATE_FEED_URL` 覆盖），超时 8s，失败只记日志不打扰用户；结果写 `data/update.json`（`last_check`、`latest`、`notified_version`、`download` 状态）。
- **比较**：自实现 semver 比较（去 `v` 前缀、数字段 + 预发布段），拒绝低于当前版本的「降级」。
- **后台节奏**：服务启动时检查一次 + 每 `UPDATE_INTERVAL_HOURS`（默认 6）一次；不需要 SSE，前端直接读缓存。
- **兜底源**：`latest.json` 失败时可退回 GitHub API `releases/latest`，或解析 `releases.atom`（无频率限制，适合高频轮询）。
- **下载**：流式写入 `data/update/`，边下边算 sha256；暴露 `received/total` 供前端轮询；大小写限（例如 300MB）防异常。
- **应用**：
  - 安装版：`subprocess.Popen([installer, "/VERYSILENT", "/SUPPRESSMSGBOXES", "/CLOSEAPPLICATIONS", "/RESTARTAPPLICATIONS", "/NORESTART", "/LOG=..."])`，随后 `os._exit(0)`；
  - 绿色版：解压到 `data/update/staging/`，启动 `updater.bat <install_dir> <staging_dir> <pid>`，随后退出；
  - 源码运行（`sys.frozen == False`）：返回「请 git pull」。
- **通知**：发现新版本且 `Pusher.configured` 时，复用 [push.py](../app/push.py) 发 Bark/ntfy（`notified_version` 去重，每版只推一次）。

### 2. API（都走现有 `X-Auth-Token`）

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/api/update` | 当前版本、最新版本、发布说明、状态（idle/downloading/ready/error）、进度、配置 |
| POST | `/api/update/check` | 强制检查（设置页按钮） |
| POST | `/api/update/download` | 开始后台下载（重复调用幂等） |
| POST | `/api/update/apply` | 校验并启动安装器，响应后退出 |
| GET | `/api/update/progress` | 下载进度（前端 1s 轮询） |

### 3. 前端

- 设置页在 [settings.html:532](../web/settings.html#L532) `sec-other` 后新增 `sec-about`（「07 关于与更新」）：当前版本 / 最新版本 / 更新内容 / 检查更新 / 下载并重启 / 通道与源。样式复用现有 `card`、`btn-primary`、`btn-secondary`。
- 首页 [app.js:1329](../web/app.js#L1329) `renderBanner()` 增加更新横幅：「v0.3.0 已发布 · 点击更新」→ 跳设置页；`localStorage` 按版本号记住「稍后」，不反复打扰。
- 更新中显示遮罩提示「正在更新，页面会短暂断开，完成后自动恢复」；应用重启后自动打开浏览器。
- 页面轮询间隔已有 [app.js:6](../web/app.js#L6)（60s），更新状态只读本地缓存，开销可忽略。

### 4. 点击「更新」的完整时序

1. 前端 `POST /api/update/download` → 服务端下载到 `data/update/`，进度可查；
2. 下载完 → sha256 与清单比对 → 状态 `ready`；
3. 用户点「立即重启并更新」→ `POST /api/update/apply`；
4. 服务端再校验一次 → 启动安装器（静默）→ 返回 `{"will_restart": true}` → 1s 后进程退出；
5. 安装器 `CloseApplications` 关闭旧进程 → 覆盖 exe/_internal/web → `[Run]` 重新拉起；
6. 新版本启动：检查 `--stop` 残留、重建 PID、打开浏览器；设置页版本号变化。

## 四、安全

- 清单与安装包都走 HTTPS；`sha256` 必须来自同一份清单，且**下载后强制校验**，不匹配直接删除。
- 版本只增不降；清单非法 / 字段缺失 → 拒绝更新。
- 非 GitHub 源（镜像）必须一样校验 `sha256`；如果要走第三方镜像，建议再加 **minisign 签名**（CI `minisign -Sm`，App 内置公钥验证），否则镜像可被替换成恶意安装包。
- 可选 **Authenticode 代码签名**：减少 SmartScreen/杀软拦截，开源个人项目可先用自签证书并文档说明信任方式。
- 默认「用户点击后才更新」，不静默自动装；`UPDATE_AUTO_DOWNLOAD` 只自动下载不自动装。
- 开源仓库不要提交 `.env`、`data/`、`output/`、`downloads/`、`tools/*.exe`（见第六节）。

## 五、国内网络：清单与安装包的可达性

GitHub 直连在部分网络下很慢，建议「默认 GitHub + 可选镜像」，App 侧全部可配：

| 环节 | 方案 |
|------|------|
| 清单 | 首选把 `latest.json` 发布到 `gh-pages`，用 jsDelivr 读：`https://cdn.jsdelivr.net/gh/<owner>/<repo>@gh-pages/latest.json`（国内快、带 CDN 缓存） |
| 安装包 | 直连 GitHub Release；失败时按 `UPDATE_MIRROR` 模板重写 URL（如 `https://ghproxy.net/` + 原 URL），仍校验 sha256 |
| 备用 | 对象存储（Cloudflare R2 / 阿里云 OSS）同步一份安装包，清单里同时给 `mirror_url` |
| 可观测 | 设置页显示「当前使用源」，下载失败给出可读原因，不弹死循环 |

配置项（`.env`）：

```ini
UPDATE_CHECK=1
UPDATE_CHANNEL=stable          # stable | beta
UPDATE_INTERVAL_HOURS=6
UPDATE_FEED_URL=               # 留空 = GitHub latest/download/latest.json
UPDATE_MIRROR=                 # 例如 https://ghproxy.net/ ，留空 = 直连
UPDATE_AUTO_DOWNLOAD=0         # 只下载不自动安装
```

## 六、开源仓库准备（当前项目还不是 git 仓库）

1. `git init` + 完善 `.gitignore`：现有内容只忽略了 `.env`、`data/`、`__pycache__`，还需要加
   `output/`、`downloads/`、`research/`、`tools/ngrok/`、`tools/cloudflared.exe`、`*.log`、`.venv/`、`dist/`、`build/`（保留 `build.iss` 目录需单独处理）。
2. 放 `LICENSE`（MIT / Apache-2.0 简单；若在意二次分发可用 AGPL-3.0，参考调研里的同类项目）。
3. `README` 面向使用者重写：安装、首次配置、更新、FAQ；开发文档放 `docs/`。
4. `SECURITY.md`（漏洞报告方式）、`CHANGELOG.md`、Issue/PR 模板。
5. 第三方合规：`ngrok` / `cloudflared` 二进制不要进仓库和 Release（许可证与体积都不合适），让 App 首次使用时从官方下载到 `tools/`；WeChatDataAnalysis 保持外置依赖并在 README 说明。
6. GitHub 话题/徽章：`release`、`license`、`CI`；可顺带提 winget / Scoop 分发（`winget-releaser` 自动发 PR）。

| 阶段 | 内容 | 估算 |
|------|------|------|
| P0 | git 化 + Release workflow + 安装器 + `latest.json` + `app/version.py` | 0.5–1 天 |
