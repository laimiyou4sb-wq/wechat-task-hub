# 微信待办 · 前端优化方案（审核稿 v1 · 已执行）

> 状态：**已被批次 1 / 批次 2 取代**，本文保留为最初的方案与审计依据。
> 实际交付见：[前端优化-批次1-交付.md](前端优化-批次1-交付.md)、[前端优化-批次2-交付.md](前端优化-批次2-交付.md)，执行契约见 [前端改造契约-batch1.md](前端改造契约-batch1.md)。
> 与本文的差异：视觉最终确定为**白底黑白极简**（而非默认的微信绿），移动端仅同步配色、不做专属交互打磨。

> 目标：在**不引入构建工具、不更换框架、不改变数据模型**的前提下，提升首屏速度、任务操作完整性、移动端手感与可访问性。

## 1. 现状与技术基线

| 项目 | 现状 |
| --- | --- |
| 技术栈 | 原生 HTML/CSS/JS（IIFE），无构建、无前端依赖；PWA + Service Worker |
| 页面 | `web/index.html` + `app.js`(45 KB/1421 行) + `styles.css`(25.8 KB/1512 行)；`settings.*` 独立页 |
| 数据 | `/api/tasks?status=all&limit=200`；前端内存态 + 乐观更新；60s 轮询 |
| 已有优点 | 骨架屏、空态/错误态、深浅色、焦点陷阱、`aria-live`、`prefers-reduced-motion`、SW 离线壳、令牌自动清理、CSS 变量体系 |
| 运行方式 | 当前服务 `127.0.0.1:8765` 正在运行；静态文件改动刷新即生效，`app/*.py` 改动需重启 |

### 1.1 实测数据（Playwright + Chrome，390×844，慢 4G + 4× CPU 降速）

| 指标 | 当前值 | 建议目标 |
| --- | --- | --- |
| 首页首屏传输 | **81.0 KB**（CSS 26.1 + JS 45.4 + HTML 10.3，未压缩） | ≤ 22 KB（gzip） |
| 全站静态资源 | 120.7 KB → gzip 31.2 KB（-74%） | — |
| FCP | **908 ms** | ≤ 700 ms |
| LCP | 1092 ms | ≤ 900 ms |
| CLS | 0 | 保持 0 |
| 主线程长任务 | 1 次 86 ms | ≤ 1 次且 < 50 ms |
| TTFF（本地） | 4 ms | — |

> 结论：**网络传输是当前首屏最大瓶颈，不是 JS 执行**。gzip 是投入产出比最高的一项。

## 2. 审计发现（按影响排序）

### 2.1 功能缺口（影响最大）

1. **不能编辑任务**。详情抽屉只有「完成 / 稍后 / 忽略 / 删除（忽略）」，没有任何输入控件；而 `PATCH /api/tasks/{id}` 已支持 `title`、`due_at`、`priority`。自动归纳出的标题或截止时间错了，只能忽略重来。新建表单副标题还写着“稍后也可以修改”，与实际不符。
2. **已忽略 / 已稍后任务完全不可见**。接口实测返回 `ignored: 1`，但前端只渲染 `pending` 与 `done`；没有入口恢复，只能直接改数据库。`snoozed` 同理。
3. **主操作不可撤销**。完成/忽略/稍后立即生效；完成项还能去「已完成」找回，忽略项没有出口。
4. **重复且误导的动作**。「忽略」与「删除（忽略）」效果完全相同，都只是 `status=ignored`，没有真删除接口。
5. **新建任务没有优先级**（接口支持）；**备注 notes 无法修改**（`TaskPatch` 未包含 `notes`）。

### 2.2 交互与可访问性

6. **每次写操作后整表重渲染，焦点丢失**。实测：键盘聚焦复选框并切换后，`document.activeElement` 变为 `BODY`；60s 轮询同样会打断键盘用户。
7. **触控热区偏小**：任务复选框 24×24、顶部图标按钮 36×36、抽屉关闭按钮 32×32（移动端建议 ≥44×44）。
8. **次要文字对比度不足**：`--text-3 #8b939d` 在白色上仅 **3.11:1**、在页面底色上 2.87:1；提醒色 `--warn #b76a00` 为 4.14:1、`--green-text` 4.38:1。均低于 WCAG AA 的 4.5:1。
9. **语义结构问题**：任务卡片是 `li[role=button]`，内部又嵌了 `button[role=checkbox]`；交互元素嵌套不合法。优先级只用一个小圆点颜色表达，读屏无信息。
10. **移动端手势缺失**：抽屉不能下滑关闭，列表不能下拉刷新，没有左滑快捷操作。

### 2.3 性能与工程质量

11. **静态资源零压缩**：响应头无 `content-encoding`。首页 81 KB → gzip 20.4 KB。
12. **无 Cache-Control**：`StaticFiles` 只给 ETag/Last-Modified；导航请求被 SW 以 `cache: no-store` 拉取 10 KB HTML。
13. **写操作多一次全量请求**：每次 PATCH 成功后还会 `loadTasks()` 再 GET 一次；叠加 60s 轮询 / visibilitychange / online 刷新。
14. **SW 版本靠手改**：`CACHE_NAME = 'wechat-todo-shell-v3'`，改前端资源必须同步 bump，否则可能新旧资源混用。
15. **单文件继续膨胀**：`app.js` 45 KB / `styles.css` 26 KB；本轮不建议拆模块或上构建，保持零依赖。
16. **无自动化前端回归**：仓库只有后端 pytest；前端改动靠人眼。

### 2.4 信息架构与视觉

17. 「今天」把**逾期 / 今天到期 / 无截止时间**混在一起，没有分组、没有逾期计数，容易漏事。
18. 「已完成」只有单一列表；完成时间不是分组依据，已忽略/稍后也没有子视图。
19. 无搜索、无筛选；任务多时只能来回切 tab。
20. 截止时间依赖原生 `datetime-local`，手机上选取成本高。
21. 设置页移动端长 **2766 px**（5 张卡、16 个输入），头部不吸顶、无未保存提醒、无快速定位。
22. 空态只有文案没有 CTA；toast 只是提示，不能承载“撤销”；错误提示在横幅和空态里重复。

## 3. 优化目标与原则

### 3.1 原则

- **零构建、零前端依赖**，继续原生 JS + PWA；不迁移 React/Vue。
- 保留现有视觉语言与信息架构，做“精修”，不做推倒重来。
- 后端最多做**配置级小改**（gzip；可选 notes 字段），不改数据模型、不改 API 语义。
- 每批改动可独立验收、可回滚；先备份（当前目录不是 git 仓库）。

### 3.2 量化目标

| 维度 | 目标 |
| --- | --- |
| 首屏 | 慢 4G+4×CPU 下 FCP ≤ 0.7s、LCP ≤ 0.9s、CLS = 0 |
| 传输 | 首页 gzip 后 ≤ 22 KB |
| 操作完整性 | 所有任务字段（标题/截止/优先级）可编辑；忽略/稍后可在界面找回 |
| 安全性 | 完成/忽略/稍后 5 秒内可撤销 |
| 可访问性 | 次要文字 ≥ 4.5:1；主要触控目标 ≥ 44px；键盘操作不丢焦点；无嵌套交互元素 |
| 稳定性 | 无控制台报错；320/390/768/1280 宽度无横向滚动 |

## 5. 详细设计

### P0-1 静态资源压缩（先做，10 分钟）

- `app/main.py` 增加 `GZipMiddleware`（`minimum_size=500`），对 HTML/CSS/JS/JSON 生效。
- 验证：`curl -I -H "Accept-Encoding: gzip"` 返回 `content-encoding: gzip`；首页 gzip 后约 20.4 KB。
- 可选追加：给 `/icons/*` 设长缓存、给 HTML 设 `no-cache`；CSS/JS 目前无内容指纹，不建议长缓存。
- 注意：改完需重启服务（launcher 管理的 uvicorn）。

### P0-2 任务编辑

- 复用 `#newSheet` 为「新建 / 编辑」双态：
  - 标题、截止时间（`datetime-local` 与 ISO 互转）、优先级三段选择（高/普通/低）。
  - 编辑态标题「编辑任务」、按钮「保存修改」、隐藏字段保存任务 id。
- 入口：详情抽屉底部新增「编辑」次按钮（同时保留完成等主操作）。
- 提交 `PATCH /api/tasks/{id}`，只发变更字段；成功后合并返回的 `task`，同步更新列表与详情。
- 清空截止时间：发送 `due_at: ""`（后端 `_clean_due` 会落为 `NULL`）。
- **备注 notes**：当前 API 不接受，方案有两种——
  - A（仅前端，推荐先行）：备注只读展示；
  - B（允许 2 行后端改动）：`TaskPatch` 增加 `notes`，`update_task` 的 allowed 已包含 `notes`，顺势打通。
- 顺带给新建表单补上优先级（接口已支持）。

### P0-3 操作撤销

- 扩展 `showToast(message, type, { actionLabel, onAction, duration })`：
  - 撤销类 toast 5s、`pointer-events: auto`、可点击「撤销」；鼠标悬停/触摸时暂停计时。
  - 完成：撤销 = `PATCH {status:'pending'}`；忽略：同样恢复 `pending`；稍后：恢复 `pending`（`snooze_until` 由后端在完成/恢复时清理或忽略）。
- 连续操作时最多保留 3 条，新的覆盖旧的；撤销后焦点回到对应任务。

### P0-4 状态视图（找回已忽略/已稍后）

- 「已完成」tab 内加分段控件：`已完成 N` / `已忽略 N` / `稍后 N`（N 前端按 `state.tasks` 计算）。
- 三个子列表共用卡片样式；「已忽略」提供「恢复」；「稍后」显示剩余时间并提供「立即恢复」。
- 原有 tab 徽标仍只显示已完成数，避免 5 个 tab 在 320px 挤压。
- 数据来源：`status=all` 已返回所有状态，无需新增接口；若任务超过 200 条，计数以服务端 `counts.done` 为准，忽略/稍后为近似值（后续分页再处理）。

### P0-5 焦点与渲染稳定性

- 把 `renderList()` 从“全量 `replaceChildren`”改为**按 id 的增量更新**：
  - 维护 `Map<id, HTMLElement>`；新增插入、删除移除、状态变化只改对应卡片。
  - 列表变化后若 `document.activeElement` 原在列表内，按 `data-id` 恢复焦点；原项被移出当前 tab 时，聚焦同位置下一项，否则聚焦 tab。
- 用 `requestAnimationFrame` 合并同一帧内的多次渲染（乐观更新 + 轮询同时到达时）。
- 60s 轮询在用户有焦点/抽屉打开时降低频率或只更新数据不重绘，避免打断。
- 验收：键盘 Tab 到复选框 → 空格完成 → 焦点仍在列表内；连续轮询 3 次不丢焦点。

### P0-6 触控热区与对比度

- 复选框：视觉 24px 不变，用 `::after` 扩大命中区到 44×44，避免挤压布局。
- 顶部图标按钮 36 → 44（可用内边距/负外边距处理视觉尺寸）；抽屉关闭 32 → 40 可视 + 44 命中。
- 颜色调整（需同时验证深浅色）：
  - `--text-3` → 约 `#6b7280`（白底 4.6:1）
  - `--warn` / `--due-today` → 约 `#955600`（5.0:1）
  - `--green-text` → 约 `#04703a`（5.2:1）
- 卡片 `aria-label` 补充优先级与状态；优先级圆点加 `sr-only` 文本。
- 卡片结构改为：`li` 容器 + 内部「打开」按钮 + 独立复选框兄弟节点，消除嵌套交互元素。

### P1-1 时间分组

- 今天：`逾期`（红色小标题 + 计数）/ `今天` / `待安排`（无截止时间）三段；逾期项置顶。
- 本周：按天分组（明天/周三…），组标题吸顶。
- 已完成：「今天完成 / 昨天 / 更早」分组，卡片显示完成时间。
- 保持现有 tab 数量与计数口径不变。

### P1-2 搜索与筛选

- 顶部加搜索入口（图标按钮展开输入，或 `search` 输入框吸附在 tab 下）。
- 本地检索 `title + notes + group_name + 来源原文仅标题匹配`，300ms 防抖，跨状态显示并带状态 chip；空结果有明确文案。
- 附加筛选：高优先级 / 有截止时间 / 仅当前 tab；`Esc` 关闭，移动端键盘弹出时保持布局。

### P1-3 快捷截止时间

- 新建/编辑表单的截止时间上方加 chips：`今天 18:00`、`明天 09:00`、`本周五 18:00`、`清除`，选中态与 `datetime-local` 双向同步。
- 时间计算用本地时区，跨天/周一边界需单测式验证（Playwright 内断言）。

### P1-4 设置页可用性

- 头部 `position: sticky`，返回键与当前分区始终可见。
- 分区锚点导航（LLM / 推送 / 消息范围 / 手机同步），滚动高亮。
- 表单脏检查：修改后显示吸底保存条；返回时 `beforeunload` 确认（仅脏状态）。
- 长卡片可折叠（默认展开当前/有配置的卡片）。
- 不改设置项语义与保存接口。

### P1-5 交互细节

- 同步状态：字号 11 → 12，文案改为「已同步 · 刚刚」/「同步失败，点此重试」，可点击重试。
- 空态增加「新建任务」CTA；错误态文案收敛为一条主文案 + 重试。
- 列表新增/移除项做 120-160ms 的轻量过渡（遵守 `prefers-reduced-motion`）。
- 完成/忽略后滚动位置保持；tab 切换保留滚动记忆（可选）。

### P1-6 抽屉手势与下拉刷新

- 抽屉：把手/头部区域按住下滑超过 96px 或速度阈值则关闭，回弹动画；不与内部滚动冲突。
- 下拉刷新：仅当 `scrollY <= 0` 且无弹层时启用，指示器 56px 起步，失败有错误 toast；桌面端隐藏。
- 两者都保留按钮作为无障碍替代。

### P2（可选，另行确认）

- **桌面双栏**：≥960px 时左侧列表、右侧详情，抽屉退化为滑入面板；`max-width` 从 720 提升到 1120。
- **左滑操作**：左滑露出「完成 / 稍后」，右滑编辑；同一时间只开一个；提供键盘等价操作。
- **离线写队列**：IndexedDB 存 PATCH/POST，联网重放；头部显示「待同步 N 条」；解决冲突以服务端 updated_at 为准。
- **PWA 角标/统计**：`navigator.setAppBadge(count)`（支持的平台）；首页加本周完成率小统计。
- **真正的删除**：需要后端 `DELETE /api/tasks/{id}`，建议与「清空已忽略」一起做。

## 6. 视觉打磨建议

### 6.1 保留

微信绿 `#07c160`、16px 圆角卡片、底部抽屉、系统中文字体栈、跟随系统的深浅色、轻阴影与低饱和背景。

### 6.2 强化

- **字体层级**：11/12/13/15/17/20 六档，正文 15、次要 12；行高统一 1.45-1.6。
- **间距节奏**：4/8/12/16/24 的 8pt 栅格；卡片内 14 → 16，列表间距 8 → 10，视觉更松弛。
- **状态色语义**：逾期红、今天琥珀、明天蓝、普通灰；颜色之外增加文字/图标冗余。
- **焦点态**：统一 2px 高对比焦点环（绿底按钮改深色描边，避免绿上绿）。
- **空态**：图标 + 一句说明 + 主 CTA，替换目前纯文案。
- **深色模式**：卡片边框略提亮、阴影加深；检查 FAB 焦点环、badge 对比度。

### 6.3 视觉方向（可选）

- **方向 A（推荐）精修现有**：不改变布局骨架，只做层级、间距、状态色、空态、动效打磨。风险低，1 批完成。
- **方向 B 任务管理风**：顶部增加统计条（今日完成/逾期/本周）、时间分组、优先级筛选条；信息密度更高。

## 8. 验收标准

## 9. 风险与回滚

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 无 git 仓库 | 改坏难恢复 | 批次 0 全量 zip 备份；每批改动前再备份 |
| SW 缓存旧资源 | 用户看到新旧混合 | 每次改前端资源 bump `CACHE_NAME`；验收前 DevTools 清缓存 |
| 改 `main.py` 需重启 | 服务短暂中断 | 选低峰期，重启后 `curl` 验证 |
| 乐观更新与撤销竞态 | 状态回滚错误 | 以任务 id + `updated_at` 校验；撤销请求串行化 |
| 编辑影响 CalDAV | 手机端任务不一致 | 改完触发一次同步检查；保留 `due_at`/`snooze_until` 语义 |
| iOS 手势/日期控件差异 | 交互不一致 | 真机验证；原生控件作为兜底 |
| 全量 DOM 改增量 | 引入渲染 bug | 保留旧渲染函数作 fallback，逐 tab 切换验证 |
