# 前端优化 · 可读性专项（字号放大 + 随屏宽自适应）

> 交付时间：2026-10-26　状态：**待验收**
> 触发：用户反馈「当前前端效果较好但可读性太差，需要增大字体、增加适配」。
> 原则：只调字号/行高/间距/栏宽，不改布局骨架、不改类名、保持白底黑白极简与零彩色。

---

## 1. 做法

在 `web/styles.css` 末尾追加「可读性字号阶梯」覆盖段：用 7 档 CSS 变量 + `clamp()` 同时覆盖移动端与桌面字号，字号随视口宽度平滑放大，不再出现「2K 屏上字还是 13px」的问题。

```css
:root {
  --fs-mono:  clamp(10.5px, calc(.18vw + 8px),   13px);   /* 分组标题、meta 标签 */
  --fs-xs:    clamp(11.5px, calc(.20vw + 8.4px), 14px);   /* 列表副标题、优先级胶囊 */
  --fs-sm:    clamp(12.5px, calc(.25vw + 8.5px), 15.5px); /* 元信息、来源、备注 */
  --fs-md:    clamp(14px,   calc(.30vw + 9.2px), 17px);   /* 导航、按钮、输入框 */
  --fs-base:  clamp(15px,   calc(.35vw + 9.4px), 18.5px); /* 正文 */
  --fs-lg:    clamp(16.5px, calc(.40vw + 10px),  20px);   /* 列表标题 */
  --fs-xl:    clamp(20px,   calc(.55vw + 11.2px), 26px);  /* 详情标题、品牌 */
}
```

同步调整（避免放大后拥挤/截断）：任务行内边距 10×12→12×14、行距 4px；勾选框与批量复选框 16→18px；左导航 196→208px、导航项高 32→36px；详情栏 1024–1599 由 388→**420px**（≥1600 时 460–820px 自适应）；列表头 / 批量条 / Toast / 详情 footer 内边距随字号微调；移动端输入框统一 16px（避免 iOS 聚焦自动缩放）。

## 5. 使用与回滚

- 刷新 http://127.0.0.1:8765 即可（SW 升到 v9，首次打开可能需再刷新一次）。
- 浏览器 Ctrl + `+/-` 缩放仍然有效；若觉得某个断点偏大/偏小，改 `--fs-*` 的 clamp 上下限即可，不需要动其他规则。
- 回滚：`output/backup/batch3-20261025-234234.zip` 里是放大前的 `web/styles.css`、`web/settings.css`，覆盖后刷新即可。
- 已知取舍：2560 下详情标题 27.4px 视觉偏大（clamp 上限 26px + 字重），如果嫌大可以把 `--fs-xl` 上限收到 24px。
